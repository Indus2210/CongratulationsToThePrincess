# Как опубликовать сайт через GitHub Pages

Полная инструкция с нуля — от создания репозитория до рабочей ссылки на сайт.
Git у тебя уже установлен (`git version 2.55.0`), репозиторий в папке сайта пока не создан.

## Важно про приватность (прочитай перед началом)

GitHub Pages — это бесплатный хостинг статических сайтов. Сайт будет опубликован
по публичной ссылке вида `https://твой_логин.github.io/имя-репозитория/`.

- Ссылку никто не найдёт сам по себе (она не в поиске, не в общем каталоге) — но
  **любой, кому ты её дашь или кто её угадает/увидит**, сможет открыть сайт.
- Сам **репозиторий можно сделать Private** (код и фото не будут видны в поиске по
  GitHub и в твоём профиле) — опубликованная страница при этом всё равно доступна по
  прямой ссылке всем, это особенность GitHub Pages, а не утечка данных.
- Если это устраивает (а для личного подарка по ссылке — обычно да), можно продолжать.

## Шаг 1. Создай репозиторий на GitHub

1. Зайди на [github.com](https://github.com), войди или зарегистрируйся.
2. Нажми **+** в правом верхнем углу → **New repository**.
3. Имя репозитория, например `alina-birthday`.
4. Видимость — **Private** (рекомендую, см. выше).
5. Остальное не трогай (не добавляй README/.gitignore/лицензию).
6. **Create repository**.
7. Скопируй ссылку репозитория со страницы, которая откроется — она вида:
   `https://github.com/твой_логин/alina-birthday.git`

## Шаг 2. Отправь файлы сайта на GitHub

Два способа — выбери любой, результат одинаковый.

### Вариант А — через командную строку (git)

Открой терминал в папке сайта и выполни по очереди:

```bash
cd "E:\Сайт для поздравления"
git init
git add .
git commit -m "Сайт-поздравление для Алины"
git branch -M main
git remote add origin https://github.com/твой_логин/alina-birthday.git
git push -u origin main
```

Если это первый коммит на компьютере и Git попросит имя/почту — выполни:

```bash
git config --global user.name "Твоё имя"
git config --global user.email "твоя_почта@example.com"
```

...и повтори `git commit -m "Сайт-поздравление для Алины"`, затем остальные команды.

При `git push` браузер может открыть окно входа в GitHub — подтверди.

### Вариант Б — просто перетащить файлы (без командной строки)

1. На странице только что созданного репозитория найди ссылку **uploading an existing
   file** (она есть на пустом репозитории, в середине страницы) и нажми на неё.
   Если репозиторий не пустой — наверху есть кнопка **Add file → Upload files**.
2. Открой папку `E:\Сайт для поздравления` в проводнике рядом с окном браузера.
3. Перетащи в область загрузки на странице GitHub:
   - файл `index.html`
   - файл `README.md`
   - всю папку `photos` целиком (GitHub сохранит структуру папки — это важно,
     сайт ссылается на файлы как `photos/имя-файла`).

   Можно перетаскивать всё за один раз, выделив файлы и папку `photos` вместе.
4. Внутри `photos` не обязательно грузить файлы `*_sound.mp4` (`friends-night_sound.mp4`
   и т.п.) — они тяжёлые и на сайте не используются, это просто твои исходники со звуком.
5. Дождись, пока все файлы загрузятся (прогресс виден на странице).
6. Внизу страницы впиши сообщение коммита, например «Сайт-поздравление для Алины»,
   и нажми зелёную кнопку **Commit changes**.

Ограничения веб-загрузки: не больше 100 файлов за раз и каждый файл до 25 МБ — у тебя
все файлы в пределах этого (даже `*_sound.mp4` весят меньше), так что всё поместится.

## Шаг 3. Включи GitHub Pages

1. На странице репозитория на GitHub зайди в **Settings** (вкладка сверху).
2. В левом меню — **Pages**.
3. В блоке **Build and deployment → Source** выбери **Deploy from a branch**.
4. Ниже, **Branch** — выбери `main`, папка — `/ (root)`.
5. **Save**.
6. Подожди 1–2 минуты и обнови страницу — сверху появится зелёный блок с адресом сайта:
   `https://твой_логин.github.io/alina-birthday/`

Открой эту ссылку — должен загрузиться `index.html`.

## Если меняешь сайт после публикации

Через git:

```bash
cd "E:\Сайт для поздравления"
git add .
git commit -m "Что поменял"
git push
```

Без git — зайди в репозиторий на GitHub, открой изменённый файл (например `index.html`),
нажми карандаш (**Edit**) для правки текста или, для замены файла целиком, удали старый
и загрузи новый через **Add file → Upload files** (новый файл с тем же именем заменит
старый).

В любом случае сайт на GitHub Pages обновится сам в течение минуты-двух — ничего
в настройках Pages трогать не нужно.

## Если ссылка не открывается

- Подожди ещё пару минут — первая публикация иногда занимает до 10 минут.
- Проверь в Settings → Pages, что статус зелёный («Your site is live at ...»).
- Если открываешь из России и видишь ошибку/таймаут — попробуй ещё раз позже или с
  другой сети: доступ к GitHub Pages у некоторых провайдеров бывает нестабильным.
